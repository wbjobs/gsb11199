# IndexedDB 批量写入 Demo

向 IndexedDB 批量写入 10,000 条记录，实时展示进度、成功/失败统计，支持失败重试与刷新恢复。

## 运行

Web Worker 需要通过 HTTP 访问（`file://` 下不可用）：

```bash
cd <本目录>
python3 -m http.server 8000
# 打开 http://localhost:8000
```

## 技术栈

- IndexedDB：数据存储（`records` 对象仓库 + `meta` 任务状态仓库）
- Web Worker：所有写入在 `worker.js` 中执行，不阻塞 UI
- DOM：统计数字、按钮、日志、提示条
- Canvas：进度条（绿=成功，红=失败）

## 设计要点

- 每批 500 条一个事务，数据与任务状态（done/failed 列表）在**同一事务**提交，保证刷新后状态精确恢复
- 页面刷新后重新打开页面，会提示「检测到未完成任务」，可继续写入剩余记录
- 失败重试只重写失败项，成功的记录不重复写

## 异常处理与验收对照

| 场景 | 行为 |
| --- | --- |
| 配额不足 | 捕获 `QuotaExceededError`，暂停任务并提示，本批计入失败，可释放空间后重试 |
| 事务中断 | 捕获 `AbortError`，该批计入失败并继续后续批次，可重试 |
| 版本冲突 | 其他上下文升级版本时 `onversionchange` 关闭连接并提示；「模拟版本冲突」按钮可演示 |
| 隐私模式 | IndexedDB 打开失败或配额过小时降级为内存模拟写入，页面不崩 |
| 数据库被删除 | 事务报 `InvalidStateError/UnknownError` 时提示，可点「重新初始化」重建；「删除数据库」按钮可演示 |
| 页面刷新 | 每批提交后持久化任务状态，刷新后可恢复续写 |
| 失败重试 | 「重试失败项」按钮仅重写失败记录，成功后从失败列表移除 |

## 验证失败/重试流程

1. 将「模拟失败率」调到 5% 以上，点击「开始写入」
2. 完成后失败数 > 0，点击「重试失败项」
3. 重复重试，失败数最终可降为 0（模拟失败是随机的）
