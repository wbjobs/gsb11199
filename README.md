# IndexedDB 批量写入演示

向 IndexedDB 批量写入 10,000 条记录，实时展示进度（Canvas 进度环）、成功数、失败数，支持失败项重试与刷新断点恢复。

## 运行

Web Worker 需要通过 HTTP 访问，启动本地服务：

```bash
python3 -m http.server 8000
# 打开 http://localhost:8000
```

## 功能

- **批量写入**：Web Worker 中按 100 条/事务分块写入，主线程无卡顿
- **进度展示**：Canvas 进度环（绿=成功，红=失败，灰=剩余）+ 统计数字
- **失败重试**：事务中断后自动逐条重试隔离失败项；失败项可一键重试
- **断点恢复**：每个事务提交后把进度（nextIndex、失败列表、成功/失败数）写入 localStorage，刷新页面后自动从断点继续

## 异常处理

| 场景 | 行为 |
| --- | --- |
| 配额不足（QuotaExceededError） | 停止写入、保存进度、显示降级提示 |
| 事务中断（AbortError） | 自动降级为逐条重试，隔离失败项 |
| 版本冲突（VersionError） | 提示数据库版本高于应用版本 |
| 隐私模式 / 无 IndexedDB | 降级为内存写入，提示刷新后数据丢失，不崩溃 |
| 数据库被删除 | `onversionchange` / `InvalidStateError` 捕获，停止写入并提示 |
| 写入中刷新页面 | 未提交事务自动回滚，刷新后从最近断点恢复 |

## 验收方法

页面底部「故障模拟」提供：

- **随机中断事务**：勾选后开始写入，可观察到失败项产生，点击「重试失败项」全部成功
- **模拟删除数据库**：写入过程中点击，观察提示
- **模拟外部升级版本**：点击后再点「开始写入」，触发版本冲突提示
- **刷新恢复**：写入过程中刷新页面，自动从断点继续
- **配额不足**：在 DevTools 中限制存储配额（如 Chrome 的 `--disk-cache-size` 或 Application 面板）后写入
- **隐私模式**：在隐私窗口打开，自动降级为内存模式
